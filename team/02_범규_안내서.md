AI 답변을 어떤 기준으로 평가할지 정한다.

질문은 네가 직접 작성해야 한다. AI는 질문의 모호함이나 답을 유추할 단서가 있는지 검토하는 데 활용할 수 있지만, 질문 자체를 대신 만들게 해서는 안 된다.

3. 해야 할 일 — 이 순서대로1단계. 채점 기준 만들기
우리는 AI 답변에 정해진 핵심 내용이 얼마나 포함되었는지 점수로 계산한다.
기본 계산식은 다음과 같다.
점수 = 맞힌 평가 항목 수 ÷ 전체 평가 항목 수
점수는 0~1이다. 예를 들어 평가 항목이 4개이고 그중 3개를 맞혔다면 점수는 0.75다.
단, 이 계산식이 실제 코드에서 어떻게 구현되어 있는지 kore/evaluation.py와 docs/CONTRACT.md를 직접 확인하고 기록하라.
다음 내용을 작성한다.
채점 기준과 계산식
좋은 답변, 부분적으로 맞는 답변, 틀린 답변의 예시 3개
점수 차이가 실제로 무엇을 의미하는지 설명
단순한 키워드 검사의 한계 2개
예를 들어 정답의 의미는 맞지만 다른 표현을 사용하면 키워드 검사에서 틀릴 수 있다. 반대로 키워드만 나열하고 설명은 틀린 답변이 높은 점수를 받을 수도 있다.
저장 파일: docs/rubric_scale.md
점수 차이를 해석할 때는 질문 수와 평가 항목 수를 고려하라. 예시 계산을 실제 실험 결과처럼 표현하지 마라.
2단계. ContextCite 논문 읽기
논문: ContextCite: Attributing Model Generation to Context, arXiv 2409.00729
이 논문을 읽는 목적은 AI가 답변할 때 입력된 자료 중 어떤 부분이 실제로 답변에 기여했는지 기존 연구가 어떻게 측정했는지 알아보는 것이다.
다음 질문에 답한다.
문맥의 일부를 제거하거나 바꾸어 기여도를 어떻게 측정했는가?
어떤 AI 모델과 데이터로 실험했는가?
단순히 질문과 비슷한 자료를 찾는 방법과 비교했는가?
우리 가설과 겹치는 점은 무엇인가?
우리 연구에서 추가로 확인하려는 점은 무엇인가?
각 답에 논문의 실제 근거 위치를 기록한다. 예를 들어 절 번호, 표 번호, 페이지 번호를 적는다.
초록만 읽었다면 초록만 읽었다고 표시한다. 실험 방법과 결과를 실제로 확인한 뒤에만 method 또는 full로 기록한다.
저장 파일: docs/research/overlap_C.csv
3단계. 법률 문서가 준비되면 질문 7개 만들기
지용(B)이 법률 문서를 준비한 뒤 시작한다. 문서가 아직 없다면 억지로 질문을 만들지 말고 1·2단계를 먼저 완료한다.
질문을 만들 때 다음 규칙을 지킨다.
질문은 총 7개다.
쉬운 질문 2개, 중간 난이도 3개, 어려운 질문 2개 정도로 구성한다.
문서 두 개 이상을 함께 읽어야 답할 수 있는 질문을 최소 2개 포함한다.
법령 문장을 그대로 복사하지 않고 실제 사람이 물을 법한 말로 바꾼다.
질문에 정답을 알려 주는 단어를 넣지 않는다.
답을 실제 문서에서 찾을 수 있는지 확인한다.
질문마다 정답의 핵심 내용과 근거 문서 ID를 기록한다.
질문 파일의 열 이름은 다음과 같이 정확하게 유지한다.
question_id, question, expected_source_ids, domain, difficulty, split, reference_answer, rubric
근거 문서가 여러 개면 expected_source_ids에 |로 구분해 적는다. rubric은 평가 항목을 |로 구분하고 동의어는 /로 구분한다.
질문을 작성할 때는 split 값을 임시로 dev로 넣고, 기존 프로젝트에서 정한 분할 절차를 따른다. 최종 시험용(test) 질문의 결과는 열어 보거나 이용해 질문을 수정하지 않는다.
초안 파일: data/evaluation_raw.csv
최종 파일: data/evaluation.csv
4단계. 질문을 독립적으로 검토하기
질문 7개를 완성하면 AI에게 검토를 요청할 수 있다.
AI에게 물어볼 내용은 두 가지다.
질문이 모호해서 서로 다른 답이 가능하지 않은가?
질문만 보고 정답을 쉽게 추측할 수 있는 단서가 있지 않은가?
정답과 평가 기준은 검토용 질문에 함께 제공하지 않는다. AI가 질문을 새로 작성하도록 하지 말고, 발견한 문제만 보고하게 한다.
검토 결과를 보고 수정 여부는 네가 결정한다. 수정하거나 수정하지 않은 이유를 기록한다.
저장 파일: review/gpt_review_log.csv
5단계. 파일 검증하고 공유하기
Colab 노트북 03의 기존 안내에 따라 질문 파일을 처리하고 검증한다.
필수 열이 모두 있는가?
질문이 7개인가?
질문마다 근거 문서와 정답이 있는가?
여러 문서를 함께 봐야 하는 질문이 2개 이상인가?
서로 거의 같은 질문이 반복되지 않는가?
검증 오류가 없는가?
검증에 실패하면 원인을 확인하고 수정한다. 실제로 실행하지 않은 검증을 통과했다고 기록하지 않는다.
파일을 GitHub에 올릴 때는 기존 프로젝트의 절차를 따른다. knowledge.csv는 지용(B)의 담당 파일이므로 수정하지 않는다.
4. AI인 너에게 요구하는 작업 방식
어려운 용어를 쓰면 바로 쉬운 뜻을 설명하라.
한 번에 한 단계씩 안내하라.
내가 직접 읽고 결정해야 하는 부분과 네가 지원할 수 있는 부분을 구분하라.
질문을 대신 만들거나 답을 대신 채점하지 마라. 내가 작성한 질문의 모호함과 단서 노출만 검토하라.
논문에 없는 내용을 지어내지 마라. 모든 연구 주장은 실제 근거 위치와 함께 제시하라.
파일을 만들 수 있다면 실제 파일을 작성하고, 그렇지 않다면 바로 저장할 수 있는 내용을 제공하라.
기존 열 이름, 파일 이름, 데이터 형식을 임의로 바꾸지 마라.
오류가 나면 원인과 해결 방법을 쉬운 말로 설명하라.
작업 완료 시 완료된 일, 미완료 작업, 확인하지 못한 사항을 구분하라.
