1. 검토 범위


기존 20개 질문을 이번 주 1차 질문 과제의 임시 대체 세트로 정리했다. 법률 문서 776개로 구성된 team/provisional/law/knowledge.csv와 출처 로그를 저장소에서 직접 읽어 근거 ID를 대조했다.


	●	질문 수: 20
	●	난이도 분포: 쉬움 4 / 보통 8 / 어려움 8
	●	복수 문서 근거: 19개 / 단일 문서 근거: 1개
	●	질문 CSV 열: question_id, question, expected_source_ids, domain, difficulty, split, reference_answer, rubric
	●	split: 전 문항 dev 임시 지정. 이는 베타 테스트·설계 검토용이며, 최종 test 세트가 아니다.


2. 저장소 대조 결과


|점검 항목                   |결과      |
|------------------------|--------|
|knowledge.csv 행 수       |776     |
|source_log.csv 행 수      |776     |
|질문에 연결된 고유 근거 ID        |44개     |
|근거 ID 실재 여부             |44/44 존재|
|출처 로그 행 존재 여부           |44/44 존재|
|해당 ID의 `license_checked`|전부 `no` |

따라서 ID가 실제 데이터에 존재한다는 점은 확인했다. 다만 license_checked=no이고 verified_by가 비어 있으므로 출처·라이선스 확인까지 끝난 자료는 아니다. 사용자가 지정한 베타테스트 범위에서만 다루며, 최종 연구 평가셋으로 승인된 것처럼 취급하지 않는다.

4. 질문 문장·루브릭 검토


	●	질문은 법령 문장을 그대로 복사하지 않고 상황형 문장으로 구성했다.
	●	질문에 정답 루브릭을 그대로 나열하는 방식은 피했다.
	●	Q07·Q09는 적용 주체가 법령상 한정되어 있어 질문 주체를 수정했다.
	●	Q03·Q12·Q15·Q17·Q18·Q19·Q20은 실제 근거 내용과 답안의 범위가 더 잘 맞도록 수정했다.
	●	각 답안은 한 문장으로 유지했다.
	●	각 루브릭은 3개 항목으로 구성하고 |와 /를 기존 KORE 형식대로 사용했다.
	●	일부 질문은 법률적 예외·세부 요건을 짧게 요약했으므로, 법률 자문용 답변이 아니라 KORE 검색·선택 기능 점검용으로만 사용한다.


5. 프로토콜 준수 관련 결정


docs/PROTOCOL.md에 따라 test는 최종 평가에 한 번만 사용해야 하고, train·dev만 설계·튜닝·기여도 라벨링에 사용할 수 있다. 따라서 현재 20개는 모두 dev로 임시 지정했다. 실제 분할을 고정하기 전 A와 데이터 분할 절차를 확인해야 하며, split이 확정된 뒤에는 임의로 옮기지 않는다.

7. 남은 일의 경계


이번 주 1차 질문 제작 과제는 20개 CSV와 검토 기록까지 작성했다. 그러나 KORE 실행 결과를 확인하지 않았으므로 검색·선택·답변 품질이나 성능이 검증되었다고 보고하지 않는다. 또한 이 베타 자료의 사용은 법령 데이터의 라이선스 검증 완료나 최종 연구 데이터 승인을 뜻하지 않는다.
