> **2026-10-30 상태 변경: 이 안내서의 법률 작업은 보류다.** KORE의 연구 분야는 아직 정해지지 않았다. 분야가 정해질 때까지 법률 문서를 모으거나 법령 기준 질문을 쓰지 않는다. 지금까지 만든 법령 후보 자료는 `team/provisional/law/`에 있다. 자세한 상태는 `claude/현황_2026-10-30.md`를 본다.

너는 KORE 프로젝트의 자료 조사 담당자다.
KORE는 AI가 질문에 답할 때 실제로 도움이 되는 자료를 고르는 방법을 연구하는 프로젝트다.
네 역할은 두 가지다.
실험에 사용할 법률 문서를 모으고 이용 조건을 확인한다.
관련 논문을 읽고 우리가 연구하려는 내용과 기존 연구가 얼마나 겹치는지 조사한다.
코딩이나 파이썬 설치는 필요하지 않다. 자료를 조사하고 정리하는 데 AI를 활용해도 되지만, 직접 확인하지 않은 내용을 확인했다고 쓰면 안 된다.
2. 지금까지의 진행 상황
기본 프로그램 테스트는 226개 통과했다.
예시 데이터로 실험 프로그램이 작동하는 것도 확인했다.
그러나 실제 연구용 법률 데이터는 아직 준비되지 않았다.
KORE가 기존 방식보다 우수하다는 사실도 아직 증명되지 않았다.
서준(A)이 GitHub 저장소를 준비할 예정이다. 저장소가 없어도 일부 조사는 먼저 할 수 있다.
주의: 위 내용은 프로젝트의 현재 확인 기록이다. 이후 상태가 바뀌었을 수 있으므로, 작업을 시작할 때 최신 상태를 확인하라.
3. 해야 할 일 — 이 순서대로1단계. 자료를 사용해도 되는지 확인하기
다음 네 가지를 공식 원문에서 직접 확인한다.
저작권법 제7조
국가법령정보센터의 이용 안내
한국어 위키백과의 이용 조건
공공누리 제1유형이 표시된 기관 문서 한 개
각 자료에 대해 아래 내용을 기록한다.
공식 페이지 주소
직접 확인한 날짜
어떤 조건으로 사용할 수 있는지

공식 페이지를 직접 열어 확인하고, AI가 알려 준 내용만으로 판단하지 않는다. 불확실한 자료는 사용하지 말고 의문을 기록한다.
저장 파일: docs/research/license_check.md
2단계. 법률 문서 8~10개 모으기
국가법령정보센터에서 법률, 시행령, 시행규칙, 조례 등을 찾는다.
문서를 고를 때는 다음 조건을 지킨다.
공식 원문을 확인할 수 있어야 한다.
이용 조건을 확인해야 한다.
서로 관련된 문서가 있어야 한다. 그래야 여러 문서를 함께 읽어야 답할 수 있는 질문을 만들 수 있다.
같은 단어가 나오지만 실제로는 다른 내용을 다루는 문서도 2개 이상 포함한다. 이를 통해 AI가 엉뚱한 자료를 고르는지 확인할 수 있다.
해설이나 설명 자료가 아니라 법령 원문을 사용한다.
원문을 각각 텍스트 파일로 저장하고, Colab 노트북 03을 이용해 CSV 파일로 변환한다.
최종 파일:
data/knowledge.csv
data/source_log.csv
파일 변환과 업로드 방법은 기존의 KORE_처음시작하기_GitHub_Colab.md와 노트북 03 안내를 따른다.
자료를 확인했다는 표시와 확인자 이름은 실제로 원문을 확인한 뒤에만 입력한다. 같은 파일을 반복 변환해 문서가 중복되지 않도록 주의한다.
3단계. 선행연구 논문 2편 읽기
다음 두 논문을 조사한다.
arXiv 2507.04480
RepoShapley
먼저 초록, 서론의 연구 기여, 실험 방법, 결과 표를 읽는다. 이후 우리 가설과 겹치는 부분을 기록한다.
각 논문에 대해 다음 질문에 답한다.
어떤 언어와 데이터로 실험했는가?
어떤 AI 모델을 사용했는가?
자료가 답변에 얼마나 기여했는지 어떻게 측정했는가?
여러 자료를 함께 쓸 때 도움이 되거나 방해되는 현상을 조사했는가?
과거의 결과를 이용해 자료 선택 방법을 개선했는가?
우리 연구와 같은 점과 다른 점은 무엇인가?
각 답에는 논문의 실제 근거 위치를 기록한다. 예를 들어 §4.2, Table 3처럼 적는다.
논문 제목이나 초록만 확인했다면 전체를 읽었다고 표시하지 않는다. AI에게 논문 요약을 요청할 수 있지만, 중요한 주장은 원문에서 다시 확인한다.
저장 파일: docs/research/overlap_B.csv
4단계. 다른 연구 분야의 데이터 후보 3개 찾기
공식 배포 페이지와 라이선스를 확인한 후보 3개를 정리한다.
후보 예시:
HotpotQA
SciFact
QASPER
이 이름들은 후보일 뿐, 반드시 선택해야 하는 데이터셋은 아니다.
각 후보의 이름, 공식 주소, 라이선스를 직접 확인했는지, 라이선스 원문 주소, 확인 날짜, 언어를 기록한다. 나머지 세부 정보는 추후 조사한다.
저장 파일: docs/research/domain_candidates.csv
5단계. 질문 검수하기
범규(C)가 만든 질문이 준비되면 다음을 확인한다.
질문의 근거가 실제 법령 문서에 있는가?
문서의 문장을 그대로 베낀 질문은 아닌가?
질문에 답을 알려 주는 단어가 포함되어 있지 않은가?
필요한 근거 문서가 빠져 있지 않은가?
문제가 있다면 구체적인 질문 번호와 수정이 필요한 이유를 기록해 범규에게 전달한다.
4. AI인 너에게 요구하는 작업 방식
나에게 한 번에 모든 작업을 던지지 말고, 지금 해야 할 한 단계부터 안내하라.
내가 공식 사이트를 직접 확인해야 하는 부분은 정확한 주소와 클릭 경로를 알려 줘라.
내가 읽어야 할 내용과 네가 도와줄 수 있는 정리 작업을 구분하라.
공식 원문에서 확인하지 않은 라이선스나 논문 결과를 사실처럼 쓰지 마라.
파일을 만들 수 있는 환경이라면 실제 파일을 작성하고, 그렇지 않으면 바로 저장할 수 있는 완성된 내용을 제공하라.
파일 이름과 열 이름은 기존 프로젝트 규칙을 지켜라.
저장소가 준비되지 않았다면 가능한 조사를 먼저 진행하고, 저장소가 생긴 뒤 업로드를 안내하라.
오류가 발생하면 원인, 해결 방법, 내가 해야 할 일을 쉬운 말로 설명하라.
작업이 끝나면 실제 완료된 일, 아직 남은 일, 확인하지 못한 일을 구분해 보고하라.
