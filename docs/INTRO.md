# KORE 소개 (참여자용)

이 문서는 KORE가 무엇인지, 지금 어디까지 왔는지, 무엇이 아직 정해지지 않았는지 설명한다. 처음 보는 사람도 이 문서만 읽고 참여 여부를 정할 수 있게 쓴다. 기술 세부는 `README.md`, 설치와 실행은 `docs/START.md`, 역할별 작업은 `docs/TASKS.md`에 있다.

## 1. 한 문장 소개

KORE는 기존 언어모델에 붙여서 **질문에 실제로 도움이 될 지식만 골라 넘기는 방법**을 연구하는 3인 프로토타입이다. 단순 RAG(유사도가 높은 문서를 상위 k개 가져오는 방식)와 같은 조건에서 비교한다.

## 2. 아직 증명된 것은 없다

- KORE가 단순 RAG보다 낫다는 주장은 실험으로 확인되지 않았다.
- 연구 가설 H1(유사도 순위와 실제 기여도가 어긋나는가), H2(지식 조합 효과), H3(경험으로 학습한 선택기의 일반화)는 모두 검증 전이다.
- 독창성도 확인되지 않았다. 비슷한 선행연구가 있고, 그 내용은 원문으로 확인하는 중이다.
- 샘플 데이터는 배관 점검용이다. 샘플에서 나온 숫자는 결과로 인용하지 않는다.

## 4. 아직 정해지지 않은 것

1. **분야**: 법령을 그대로 쓸지, 다른 전문 분야로 바꿀지. 분야마다 G2 게이트(모델이 이미 아는지, 근거 조각을 자를 수 있는지, 이용 조건이 공개를 막지 않는지)를 통과해야 한다.
2. **데이터 확인 범위**: 출처 원문과 이용 조건을 행별로 확인할지, 표본만 확인할지.
3. **공개 여부**: 데이터와 결과를 공개할지. 결과가 좋을 때만 공개하면 선택 편향이 생기므로, 공개 결정은 결과를 보기 전에 한다.

## 5. 이런 사람이 참여하면 좋다

- **데이터·선행연구**: 논문을 읽고 근거 위치를 찾을 수 있는 사람. 공공 자료의 이용 조건을 직접 읽을 수 있는 사람.
- **평가·실험**: 질문을 쓰고 정답 근거를 붙이는 일을 꼼꼼히 할 수 있는 사람. 채점 기준을 세울 수 있는 사람.
- **개발**: 파이썬을 쓸 줄 알고, 테스트를 돌리고 결과를 기록할 수 있는 사람. 개발 경험이 부족해도 AI 도구로 일하는 방식을 배울 의지가 있으면 된다.

필요한 것은 무료 Google Colab 계정과 GitHub 계정이다. 돈이 드는 API는 쓰지 않는다.

## 6. 일하는 규칙

- 하지 않은 실험이나 결과를 만들지 않는다. 사실과 추론을 구분해서 적는다.
- 질문과 평가 기준을 쓴 뒤에 튜닝하지 않는다. 최종 평가 데이터(test)는 최종 평가 때만 연다.
- 변경은 작게 나누고, 바꿀 때마다 테스트를 돌린다. 테스트가 깨진 코드를 완료라고 하지 않는다.
- 모든 작업 결과에는 보고서를 붙인다. 무엇을 했고, 무엇을 검증했고, 무엇이 남았는지 적는다.
- 비밀 키와 개인정보는 저장소에 넣지 않는다.

## 7. 참여 방법

1. 이 문서와 `README.md`를 읽는다.
2. 팀에 참여 의사를 알린다. 팀장(A)이 GitHub 조직에 초대한다.
3. 개인 토큰을 만들고 승인을 받은 뒤 `docs/START.md`를 따라 저장소를 받는다.
4. `docs/TASKS.md`에서 자기 역할 항목을 찾아 시작한다.
