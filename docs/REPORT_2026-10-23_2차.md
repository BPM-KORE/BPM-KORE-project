## 0. 먼저 읽을 다섯 가지

1. **정한 것은 모두 제안이다.** 언어(한국어), 모델(Qwen3-4B-Instruct-2507), 분야 3개, 규모, 분할, 주 지표, 게이트를 `docs/DECISIONS.md`에 근거와 함께 적었다. 세 사람이 동의해야 확정이다.
2. **돈이 드는 것은 없다.** 오픈 모델을 무료 Colab GPU에서 돌리는 경로를 만들었다. GPT·Claude·Gemini API는 쓰지 않기로 했고 이유를 적었다(비용, 로그확률 접근 불가, 버전 고정 불가).
3. **GPU가 필요한 부분은 여기서 한 번도 실행하지 못했다.** 모델 로딩, 한국어 생성 품질, 속도, 로그확률 계산은 미검증이다. `notebooks/02_colab_gpu_run.ipynb`의 2번 셀이 첫 확인이고, 그게 통과해야 이후 계획이 유효하다(G1).
4. **test 36개로는 작은 차이를 구분하지 못한다.** 질문별 차이의 표준편차를 0.40으로 가정하면 검출 가능한 최소 차이가 0.19다. "구분하지 못했다"가 주 결과일 수 있고, 그 경우 기여도 라벨링 분석이 연구의 중심이 된다.
5. **발견해서 고친 결함 하나**: 질문을 더 만든 뒤 `split`을 다시 돌리면 이미 train/dev에서 쓴 질문이 test로 옮겨질 수 있었다. `--keep-from`과 덮어쓰기 거부를 넣었다.

## 2. 검증한 것

- 전체 테스트 **210개 통과**: 파이썬 3.11, 3.12, 3.13에서 확인. 3.10은 이 환경에 설치되어 있지 않아 실행하지 못했다(문법은 `from __future__ import annotations`를 쓰는 3.10 호환 형태로 작성).
- 생성기의 프롬프트 조립, 설정 검사, 오류 경로는 가짜 토크나이저로 시험했다.
- 라벨링 분석은 점수표를 손으로 만든 가짜 점수기로 시험해서, 순위 불일치·시너지·간섭·상수 점수 같은 경계 사례의 기대값을 확인했다.
- 가짜 데이터(발명한 문서와 질문)로 `ingest → stats → split → run → screen → label → label-report → blind-export → blind-score`를 끝까지 한 번씩 돌렸다. 이 수치는 연구 결과가 아니다.
- 이번에 `docs/TASKS.md`에 적은 `ingest`(dry-run 포함), `stats`, `split`(처음, 덮어쓰기 거부, `--keep-from`) 명령을 실제로 실행해서 동작을 확인했다.
- 모델 카드(Qwen3-4B, Qwen2.5-3B, EXAONE-3.5), Colab FAQ, 공공누리 이용 조건은 페이지를 열어서 확인했다. 결과는 DECISIONS의 "확인함/확인 못 함" 표시를 따른다.
